# Learnings

- **2026-08-07** — The frontend workspace calls **`/api/agent/chat`, not `/api/chat`** (`components/landing/ai-workspace.tsx`); only the floating companion uses `/api/chat`. A whole feature was designed, tested, reviewed and live-verified against `/api/chat`, which worked perfectly the entire time — and two user-visible defects sat in the path nobody had exercised. Driving the real UI for ten minutes found both. Lesson: before declaring a backend change verified, grep the frontend for which endpoint it actually calls. "The API works" and "the product works" are different claims, and only the second one is what a user experiences.
- **2026-08-07** — A soft instruction loses to a prominent one. The agent's system prompt showed a WORKFLOW block advertising `search_youtube_videos → ingest_video → answer_question`, while the binding to the user's video was appended as `"Focus on this video."` Asked a specific question about an already-ingested video, the model followed the workflow: it searched YouTube, ingested a DIFFERENT video, answered from that one and reported "no relevant context" — the same question through `/api/chat` answered correctly from five chunks. Two costs, not one: a wrong answer, and an unrequested video written into the **production** vector store, which had to be deleted by hand. The fix was to make it a prohibition naming the video and the forbidden tool in one sentence. General lesson: when a prompt contains both a procedure and a constraint, the constraint has to be at least as prominent as the procedure, or it is advisory in practice.
- **2026-08-07** — Fixtures built on round numbers hide off-by-fraction bugs. `format_timestamp` truncates to whole seconds, so a chunk starting at 70.56s is shown to the model as `[01:10]`; the summarisation prompt tells the model to copy that label EXACTLY, and the validator then tested `70.56 <= 70.0` and dropped the citation. **Every** chunk of the live video had a fractional start, so the system systematically discarded its most faithful citations — while all 280 tests passed, because every test chunk started on a whole second. Only live verification against real data exposed it. The fix matches the DISPLAYED form first (`format_timestamp(chunk.start) == format_timestamp(mark)`) and falls back to range containment. When a value is shown to a model in a lossy format and read back, compare in the format it was shown in, not the one it was stored in.
- **2026-08-07** — Webshare rotation is controlled by the USERNAME SUFFIX, not by anything in the dashboard. The configured user was `yschfeat-DE-1` against `p.webshare.io:80`: `-DE` pins the country and `-1` pins a sticky session, so every request left through the SAME exit IP — and once YouTube flagged that one IP, ingestion was dead while the account, the quota and the credentials were all fine. Testing variants took seconds and settled it: `yschfeat-DE-1` was blocked while `-rotate`, `-DE-2`, `-DE-3`, `-US-1` and the bare username all worked. The fix is to change `-DE-1` to `-rotate` in `WEBSHARE_PROXY_URL`; password and host stay. Prefer `-rotate` over the next sticky index — a fresh IP per request means a single ban can no longer stop ingestion, whereas `-DE-2` is just the next IP to be banned. Diagnostic order that works: try the transcript API without a proxy, then with it, then try several username suffixes; if the suffixes differ, it is a sticky-IP ban, not an outage.
- **2026-08-07** — YouTube blocked BOTH ingestion paths at once: `youtube-transcript-api` returned `RequestBlocked` from a residential machine and `IpBlocked` through the configured Webshare proxy, while `yt-dlp` — the Whisper fallback's audio source — returned "Sign in to confirm you're not a bot". The proxy had worked an hour earlier, so this was a block wave, not a misconfiguration. Two lessons. First, `WEBSHARE_PROXY_URL` being set is not the same as the proxy WORKING: when its exit IP gets flagged, the symptom is identical to having no proxy at all, and the fix is to rotate the pool, not to configure anything. The 502 message used to assert "configure a proxy" unconditionally, which sent an operator to fix something already correct — it now distinguishes the two cases (`TranscriptService._blocked_detail`). Second, the Whisper fallback is unreachable in exactly this failure mode anyway: `IpBlocked` subclasses `CouldNotRetrieveTranscript`, which the 502 branch catches, while only `NoTranscriptFound`/`TranscriptsDisabled` route to Whisper. Fixing that ordering would not have helped here (yt-dlp was blocked too) but it is worth knowing before someone assumes the fallback covers blocking. Already-ingested videos are unaffected throughout — chat, retrieval and summaries read from Postgres and never touch YouTube.
- **2026-08-06** — The backend suite's WARNING count is nondeterministic: `test_speech_route.py` intermittently emits `PytestUnhandledThreadExceptionWarning` (1-3 per run, sometimes none) because an analytics `safe_track` write reaches `aiosqlite` in a worker thread AFTER the test's event loop has closed - `sqlite3.OperationalError: unable to open database file` followed by `RuntimeError: Event loop is closed`. It is pre-existing and unrelated to whatever you are changing. Two lessons: never treat the warning count as a regression signal (only pass/skip counts are stable), and never conclude "my change introduced this" from a SINGLE clean run of the old code - for anything intermittent, run the baseline several times before attributing it. Real fix, if ever wanted: await or cancel the analytics task before loop teardown.
- **2026-08-04** — Supabase shows the PROJECT url (`https://<ref>.supabase.co`) far more prominently than the database connection string, so it is the natural thing to paste into `DATABASE_URL` or `TEST_DATABASE_URL`. SQLAlchemy then fails with `NoSuchModuleError: Can't load plugin: sqlalchemy.dialects:https` — a twelve-line stack trace whose last line names neither the setting nor the mistake. It cost two debugging rounds before a `field_validator` on `database_url` was added to reject it by name. The correct value is the port-5432 entry under Supabase → Connect, with the scheme changed to `postgresql+asyncpg://`. General lesson: when a config value is easy to confuse with a lookalike, validate it where it enters, not where it is finally used.
- **2026-08-04** — A destructive test fixture guarded only by a docstring will eventually run against production, because the verification instructions tell you to aim it there: `$env:TEST_DATABASE_URL = $env:DATABASE_URL` is exactly what this project's own Phase 2a step 3 asks for, and the contract fixture deletes every row in `transcript_chunks`. It emptied the live table; only a demo video was lost. The fix is a guard that refuses when `TEST_DATABASE_URL` equals `DATABASE_URL` **or** when the target table already holds rows — checked BEFORE the delete, and written as a pure function so the safeguard is testable without the database whose absence it protects. Note the symptom was misleading: an empty table returns HTTP 200 with `result_count: 0`, which reads like a broken query rather than missing data. Check row counts before debugging retrieval.
- **2026-08-03** — In a SQLAlchemy `text()` string, never write `:name::type`. `text()` deliberately skips a `:name` that is immediately followed by another colon so it does not mangle PostgreSQL's `::` cast operator — so the bind is never substituted, Postgres receives a literal `:` and fails with `syntax error at or near ":"`. Use `cast(:name as type)` instead. The giveaway is a rendered statement where some params became `$1/$2` but one still shows `:name`. Found in `vector_store/postgres.py`; the same file binds pgvector embeddings as `cast(:embedding as text)::vector`, which works — asyncpg does NOT need `register_vector` when the parameter is routed through a core type first.
- **2026-08-03** — Run the backend suite from `backend/`, never from the repo root. `Settings` uses `env_file=".env"` resolved against the CWD, so `python -m pytest` at the root loads the real root `.env` (Webshare proxy creds, CORS, etc.) instead of test defaults — 12 tests in `test_transcript_service.py` and friends fail with what looks like a regression but is only environment bleed. `cd backend && OPENAI_API_KEY=dummy python -m pytest` is the correct invocation; the giveaway is failure paths printed as `backend/tests/...` rather than `tests/...`.
- **2026-08-03** — Supabase Free pauses a project after 7 days of low activity and
  requires a MANUAL restore; paused beyond 90 days it is deleted permanently. Neon
  behaves differently (5-minute scale-to-zero, automatic resume) — if the demo goes
  unused for weeks, that difference matters more than any latency number. Also:
  asyncpg caches prepared statements, and disabling only its own cache
  (`statement_cache_size=0`) is NOT sufficient — SQLAlchemy's asyncpg dialect
  keeps a second prepared-statement layer on top (its own
  `prepared_statement_cache_size`, defaulting to 100, plus a numeric name
  generator), so pooled connections can still collide on `__asyncpg_stmt_N__`
  and raise `DuplicatePreparedStatementError` under concurrency, never at
  startup. Fix needs all three: `statement_cache_size=0`,
  `prepared_statement_cache_size=0`, and a UUID-based
  `prepared_statement_name_func`. Apply unconditionally to every Postgres
  engine (app AND Alembic) — the SQLAlchemy-side collision isn't specific to
  Supabase's transaction pooler, so it isn't safe to gate the fix on "am I
  behind a pooler".
- **2026-08-03** — `asktube-ai.duckdns.org` timed out from this PC only (other machines + `asktube-ai.vercel.app` were fine). Cause was a leftover `hosts` line `18.157.233.122 asktube-ai.duckdns.org` — the terminated EC2 IP — added by hand during the July DNS cutover and never removed; it silently overrides correct public DNS forever. Diagnosis order that works: resolve via 8.8.8.8/1.1.1.1 AND via the local resolver and compare — if they disagree, suspect `hosts`. The fingerprint is a nonsense TTL in `Get-DnsClientCache` (571335 s vs the record's real 60 s): Windows loads hosts entries into the DNS cache with an artificially huge TTL. Never conclude "the site is down" from one machine.
- **2026-08-03** — Editing `hosts` on this PC needs more than elevation: Avast (`AvastSvc`/`AvastUI`/`AvastNM`) holds the file open, so an admin shell still fails with `IOException: being used by another process` — NOT `Access denied`. Worse, `Set-Content` truncates before writing, so the failed write left the file at **0 bytes**, wiping the Docker Desktop and `gen-webserver.local` entries. Back the file up first, and prefer read-into-variable then `[System.IO.File]::WriteAllLines`. A browser screenshot is not proof of a fix here — a failed navigation can leave the previously loaded page (and its URL) in the tab; always verify the tab's final URL, not the pixels.
- **2026-07-05 (RESOLVED same day)** — An external probe reported the live ingest path 502ing with the proxy-hint error, suggesting `WEBSHARE_PROXY_URL` was missing on Render. Re-verified at 18:00: `POST /api/videos/fWjsdhR3z3c/ingest` returned **200 with 10 chunks stored** — the proxy IS set on Render and working. Lesson kept because the failure mode is real: if ingest ever 502s with that message, the proxy env var is the first thing to check (all three forms valid, `*_URL` takes priority), and a single failed probe can also be a cold-start timeout or a video with disabled transcripts — retry with a known-captioned short video before concluding the env is broken. Demo pre-flight stays in `DEMO_DAY_RUNBOOK.md` step 0.
- **2026-07-05** — After a DNS cutover, local tests lie: this PC's resolver chain (router/VPN ignoring DuckDNS's 60s TTL) kept serving the dead EC2 IP for over an hour, first faking success (old server still up) and then faking failure (timeout after teardown). Verify cutover with EXTERNAL probes: `check-host.net/check-http` (multi-country HTTP checks) and `crt.sh` (proves cert issuance). Local `ipconfig /flushdns` doesn't help when the staleness is upstream; browser "Secure DNS" (DoH) bypasses it.
- **2026-07-05** — `curl.exe --resolve <host>:443:<ip>` TLS probes fail with schannel exit 35 on this machine even against known-good endpoints — likely Avast HTTPS scanning interfering. Don't trust local direct-IP TLS probes here; they falsely suggested Vercel had no certificate.
- **2026-07-05** — When adding an apex-style domain on Vercel (incl. PSL domains like `*.duckdns.org`), UNCHECK "Redirect apex domains to www" — DuckDNS cannot serve the `www.` variant, and the checkbox silently creates a broken redirect target.

- **2026-07-05** — pydantic-settings JSON-decodes `list[str]` fields from env vars BEFORE field validators run, so a `mode="before"` validator cannot rescue non-JSON values. `CORS_ORIGINS=https://...` (plain string) crashed startup on Render with a SettingsError until the field was annotated with `NoDecode` (fixed in 5b64f54). Symptom in browsers: unhandled 500s bypass CORSMiddleware, so fetch fails with an opaque "Failed to fetch" instead of a readable error.
- **2026-07-05** — YouTube blocks transcript requests from Render's datacenter IPs just like EC2's; `youtube-transcript-api` raises `RequestBlocked`/`IpBlocked` (subclasses of `CouldNotRetrieveTranscript`), which the service didn't catch → instant 500 on ingest. Fixed in b1e3a3d (clean 502 with proxy hint). The working fix is `WEBSHARE_PROXY_URL` in the environment.
- **2026-07-05** — DuckDNS + Vercel works: `duckdns.org` is on the Public Suffix List, so Vercel treats `asktube-ai.duckdns.org` as an apex domain and accepts an A record (216.198.79.1) — DuckDNS can't do CNAMEs. Cert issued within minutes.
- **2026-07-05** — 9 speech-route tests fail with 503 unless `OPENAI_API_KEY` is set (any dummy value works) — the route checks global settings at request time. Fresh test environments must export it before `pytest`.
- **2026-07-05** — Render deploys the `backend/` root dir with the Docker runtime (ffmpeg included, port 8000 via `PORT` env). The service URL got a suffix: `asktube-ai-q2gi.onrender.com` — a wrong hostname baked into Vercel's `NEXT_PUBLIC_API_URL` fails silently ("Search paused" UI error); the runtime fallback in api.ts only rescues *localhost* URLs, not wrong public ones.

- **2026-07-04** — `frontend/lib/analytics.ts` must NOT import from `@/lib/api`: the voice test suites (`__tests__/floating-companion-voice.test.tsx`, `__tests__/search-console-voice.test.tsx`) stub the whole module with `vi.mock("@/lib/api", () => ({...}))`, so any extra export pulled in by `analytics.ts` resolves to `undefined` and crashes `trackAnalyticsEvent` inside components. Keep the API-base fallback logic duplicated but in sync between `resolveApiBase` (api.ts) and `resolveAnalyticsApiBase` (analytics.ts).
- **2026-07-04** — In docker-compose, keys under `environment:` override values from `env_file:`. `CORS_ORIGINS` is therefore interpolated (`${CORS_ORIGINS:-...}`) in `docker-compose.yml` so a production `.env` value actually reaches the backend container.
